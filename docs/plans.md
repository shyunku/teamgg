# team.gg 구현 계획

## 현재 스프린트

### Task #68 관리자 운영 화면

1. `user_roles`, `admin_audit_logs`, `admin_operational_events` 스키마와 순차 마이그레이션을 추가한다.
2. 기존 백엔드에 관리자 역할 확인 및 공유 비밀키 기반 내부 조회 API를 추가한다.
3. 별도 `apps/admin` 서버에 인증 프록시, 서비스 상태, 운영 개요, 이벤트 조회 API를 추가한다.
4. 기존 프론트엔드에 관리자 전용 `/admin` 화면과 계정 메뉴 진입점을 추가한다.
5. Compose, 환경변수 템플릿, 운영 문서를 갱신하고 전체 테스트·빌드를 수행한다.

## 후속 선택지

- 관리 기능이 쓰기 작업과 다중 운영자 승인 흐름까지 확대되면 독립 관리자 프론트엔드 분리를 재검토한다.
- 원문 애플리케이션 로그 검색이 필요해지면 Docker 소켓 마운트 대신 Loki/OpenSearch 같은 전용 로그 수집기를 도입한다.
- 역할 부여·회수 UI는 감사 및 재인증 정책이 확정된 뒤 별도 task로 구현한다.
### Task #61 숙련도 통계 증분 집계

1. 챔피언·숙련도·레벨 커버링 인덱스를 온라인 DDL로 추가한다.
2. 변경된 챔피언만 기록하는 dirty queue와 INSERT/UPDATE/DELETE 트리거를 추가한다.
3. 챔피언별 제한된 인덱스 범위 스캔으로 materialized aggregate를 갱신하고 DB cutoff로 동시 쓰기를 보존한다.
4. 통계와 Top 30 조회를 materialized aggregate 및 챔피언별 제한 조회로 전환한다.
5. 단위 테스트와 전체 빌드를 통과한 뒤 운영 DB에서 정확도·쿼리 계획·실행 시간·잠금 영향을 검증한다.

운영 규모 검증이 완료되기 전까지 Task #61은 WIP로 유지한다.

5. 운영 규모에서 기존 약 7.8GB 임시 공간, 수집 시간, 잠금·deadlock과 비교한다.

운영 규모 비교가 완료되기 전까지 Task #62는 WIP로 유지한다.
