운영 검증: 2026-09-24 17:12~17:20 KST에 Linux 호스트 preview-only, 운영 dry-run 및 백엔드 중단 후 제한된 no-op 실제 명령을 검증했다. 최신 8개 패치만 존재해 대상·삭제가 모두 0건이었다. 백엔드는 healthy와 통계 API 200으로 복구했다. 상세 수치와 중단/복구 기록은 [운영 검증 보고서](../reports/2026-09-24-retention-production-verification.md)에 있다.

운영 활성화: 2026-09-24 17:40 KST에 `teamgg-retention.timer`를 설치·활성화했다. 서버의 ignored `.env.retention`은 7일 주기, 최신 8개 패치, KST 02:00~04:00, 최소 디스크 여유 20GiB, 실행 계정 `ec2-user`로 설정했다. 수동 service 실행은 유지보수 창 밖에서 `outside_window`로 정상 종료됐고, 백엔드 재시작 후 healthy 및 API 200을 확인했다. cron은 설치하지 않았으며 systemd timer가 매시간 기동 조건만 확인한다.

로컬 보강(2026-10-02 16:36): 운영 대상이 없어도 검증 가능한 재실행·알림 경로를 테스트로 보강했다. Python 스케줄러 단위 테스트 12개와 retention MySQL 통합 테스트 2개를 통과했다. 같은 패키지의 `TestNumericKeyFoundationAndBackfillMySQL`은 변경 전 HEAD에서도 `MasteriesReady:false`로 실패하는 기존 문제이며 #76과 무관하다. 보강분은 아직 운영 호스트에 배포하지 않았다.

첫 실제 삭제(2026-10-02 16:47 확인): 2026-10-02 03:00 KST 정기 실행에서 패치 16.10·16.11의 6개 버전, 21,433경기가 대상이었다. work limit 10분 동안 2,500경기와 하위 행(참가자 28,024, 룬 선택 168,144 등)을 삭제하고 `work_limit`로 종료했으며 잔여는 18,933경기다. 백엔드는 18초 뒤 복구됐고 `completedAt`은 갱신하지 않아 `attemptedAt` 기준 24시간 뒤 같은 창에서 재개된다. 확인 시점 backend healthy, 기본·champion·meta-summary API 200, 루트 디스크 여유 36GiB였다. 상세는 [운영 검증 보고서](../reports/2026-09-24-retention-production-verification.md)에 있다.

속도·중단 원인 분석(2026-10-02 17:56): 운영 MySQL은 InnoDB buffer pool이 기본값 128MiB이고 DB는 약 44GiB다. 삭제 쿼리는 모두 인덱스 경로로 실행되며 DELETE 트리거도 없지만, 만료 경기 행과 보조 인덱스가 거의 모두 EBS 랜덤 읽기를 유발해 100경기 배치가 약 24초 걸린다. 100경기 분량 룬 선택 SELECT만 3.3초였다. 기존 offline 방식은 이 긴 배치의 행 잠금과 API 쓰기 경합을 피하려고 백엔드를 중단했다. 사용자 결정에 따라 백엔드를 멈추지 않는 online 모드를 기본으로 전환하고 새벽 2시간 동안 실행한다. buffer pool 증설은 같은 MySQL 인스턴스를 다른 스키마(`mips`)가 함께 쓰고 있어 별도 판단으로 남겼다.

운영 DB 조치(2026-10-02 18:14): 사용자 승인으로 `innodb_buffer_pool_size`를 128MiB에서 384MiB로 `SET PERSIST` 온라인 확장했다. 서버 RAM 3.8GiB 중 가용 약 2.1GiB이고 swap 2GiB를 이미 사용 중이어서 1GiB 대신 384MiB로 제한했다. 확장 직후 backend healthy, 주요 API 200, mysqld active를 확인했다. 과거 통합 테스트가 운영 DB에 남긴 `teamgg_retention_test_*` 픽스처 DB 2개(각 15테이블·45행)를 삭제했다. 변경분은 `c511f27`까지 push했으며 운영 배포는 사용자가 진행한다.

첫 online 실행(2026-10-03 15:25 확인): 2026-10-03 03:00 KST에 전날 work limit으로 남은 18,933경기를 백엔드 중단 없이 46분 26초 만에 모두 삭제하고 `completed=true`로 종료했다. 분당 약 408경기로 전날 offline 실행(약 250경기/분)보다 빨랐으며, buffer pool 384MiB 확장 효과로 추정한다. 부하 가드 대기와 배치 재시도는 모두 0건이었다. 하위 행은 참가자 217,962, 룬 선택 1,307,772 등이다. 실행 구간 백엔드 로그 오류는 03:36 숙련도 통계 수집 `driver: bad connection` 1건(5분 뒤 재시도)뿐이며, 같은 오류가 삭제가 없던 10-02 15:31에도 있어 삭제와 무관한 기존 현상으로 본다. backend는 계속 healthy였고 다음 실행은 7일 뒤다.

VFY 잔여: 웹훅 주소가 없어 실패·미완료 알림은 journal에만 남는다. 운영 알림 경로를 확인하면 DONE으로 전환한다.
