- 불일치 1,193행(PUUID 1,052개)은 모두 참가자와 매핑 행의 `summoner_fk`가 `summoner_numeric_keys`에 존재하지 않는 ID를 가리키고, 같은 PUUID의 현재 키는 다른 ID다. 해당 PUUID의 참가 기록은 두 ID로 나뉘어 있다.
- 표본 3건은 2026-08-31 참가자 insert trigger가 새 소환사 키 행을 만든 같은 statement에서 생성됐다(키 `created_at`과 매핑 `created_at`이 마이크로초까지 같음). trigger의 `LAST_INSERT_ID()`가 새 키 ID가 아닌 다른 값을 반환한 것으로 추정한다.
- 매핑 행을 삭제하는 코드는 없다. 동시 insert 후 롤백 시나리오는 로컬에서 정상 동작했다.
- 원인: 부모 키 백필의 `ON DUPLICATE KEY UPDATE summoner_id = VALUES(summoner_id)`가 trigger가 먼저 만든 identity 행의 ID를 새 auto-increment 값으로 바꿨다. 1,193행 모두 소환사 부모 백필이 처음 운영에서 돈 2026-08-31 15:52~17:56 KST에 생겼다. 로컬 동시 쓰기 테스트로 이 upsert만 고치면 통과하고 되돌리면 실패함을 확인했다. 처음 세운 trigger `LAST_INSERT_ID()` 가설은 재현되지 않아 폐기했다. 상세는 [보고서](../reports/2026-10-05-participant-summoner-key-renumbering.md).
- 같은 trigger 방식을 쓰는 `leagues`·`summoner_matches`의 숫자 키 불일치는 0건, `masteries_numeric_v2`의 존재하지 않는 소환사 참조도 0건이다. 영향은 참가자 1,193행과 그 매핑 행뿐이었다.
- 기존 백필 검증(`validateNumericKeyBackfill`)은 참가자를 매핑 테이블과만 비교해 이 불일치를 잡지 못했다. `35b66d2`에서 백필 upsert를 고치고 identity 테이블 직접 비교를 추가했다.
- 데이터 수정(2026-10-05 19:06): 사용자 승인 후 1,193행의 참가자·매핑 `summoner_fk`를 현재 ID로 한 트랜잭션에서 갱신했다(4초). 재검증 결과 소환사 identity 불일치 0건, 매핑 불일치 0건, backend healthy, 관련 오류 없음. 갱신 전 값은 서버 `/home/ec2-user/task70-fix-backup-20261005.tsv`에 있다.
