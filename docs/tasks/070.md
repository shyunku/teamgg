## 로컬 동시 쓰기 검증 (2026-10-02 18:51)

백엔드를 켠 채 백필하는 경우를 확인하려고 격리 MySQL 8.0에서 participant 백필과 애플리케이션 방식의 경기 저장 4개 writer를 동시에 실행하는 통합 테스트(`TestNumericKeyParticipantBackfillConcurrentWritesMySQL`)를 추가했다.

| 항목 | 결과 |
|---|---|
| 수정 전 | 백필 21회 실행 중 20회가 `1213 Deadlock`으로 실패 |
| 원인 | 백필 트랜잭션이 기본 REPEATABLE READ라서 identity upsert가 매핑 테이블 auto-increment PK 끝(supremum)에 gap lock을 잡았다. 신규 identity insert가 모두 막히고, PUUID identity를 먼저 잡은 경기 저장 트랜잭션과 교착이 생겼다 |
| 수정 | 숫자 키 백필 트랜잭션을 애플리케이션 경기 저장과 같은 READ COMMITTED로 시작 (#71 하위 백필도 같은 함수 사용) |
| 수정 후 | 3만 행 3회와 20만 행 1회 모두 백필 교착 0건, 경기 저장 오류 0건(기존 앱 재시도로 흡수된 충돌 6~9회), 정합성 검증 통과 |

운영 실행 전 이 수정이 포함된 이미지 배포가 필요하다.
