## 목적

운영 디스크 증가를 통제하기 위해 오래된 경기 데이터를 안전하고 재시작 가능한 작은 배치로 삭제한다. S3 아카이브는 사용하지 않는다.

| 안전장치 | 기본 dry-run, 명시적 delete/offline 승인, 배치·timeout·work limit, 자식 → 부모 트랜잭션 삭제 |
| 중단 기준 | 디스크 여유 12GiB 미만, lock wait, API 장애 |
| 운영 상태 | 백엔드 healthy, 주요 API 200, DataExplorer 비활성, 디스크 약 16GiB 여유 |

## 구현 및 검증

- `cleanup-retention` 유지보수 명령과 운영 문서를 추가했다.
- 사용자 계정·내전·리플레이 데이터와 stale 소환사는 삭제 대상에서 제외했다.
- 대형 테이블의 full scan을 피하도록 PK 기반 join delete로 최적화했다.
- 숫자 match/participant identity는 상세 캐시가 아니므로 삭제하지 않고 재수집 시 동일 ID를 재사용한다.
- 전체 Go 테스트·vet·build와 임시 MySQL DB 통합 테스트를 통과했다.
- 운영에서 smoke test 후 1시간 제한 run 3회로 전체 대상을 정리했다.
